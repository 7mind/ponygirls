# Chronicle dashboard

React / TypeScript / Vite. Production contains no fixtures, external assets, fonts, uploads, or browser credential storage. All HTTP and WebSocket operations use the generated Baboon v1.4 classes and JSON codecs in `../generated/typescript/`; generated files are not maintained here.

## Build and verify

Node 24 and npm 11; exact dependency versions are locked in `package-lock.json`.

```bash
npm ci
npm test
npm run typecheck
npm run build
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 \
PLAYWRIGHT_BROWSERS_PATH=/path/to/playwright-1.64.1-browsers \
  npm run test:browser
```

The provisioned development browser directory is `/nix/store/3jc1mc38kwqi6vqzns8z1nqq70affw5k-playwright-browsers`. Tests never download browsers. `npm test` uses Node's experimental TypeScript transformation for generated enums, plus a test-only resolver for the generator's `.js` imports. Production uses Vite's TypeScript compilation.

Serve `dist/` on the **same origin** as `/api/login`, `/api/ws`, and the remaining server API. TLS and the server's exact Origin, session-cookie, and CSRF policies are required in deployment. The dashboard has no cross-origin/token configuration. Vite caches are source-local under ignored `.cache/vite`, including when an identical pinned dependency tree is shared read-only. `npm run dev` starts Vite on loopback; a local same-origin API reverse proxy is needed to use a real server. The browser fixture instead serves a separate, test-only entry through Vite.

## Interface

- Theme settings are available before sign-in: System (default), Light or Dark. Only the non-secret `chronicle.theme.preference` value is persisted; cross-tab changes synchronize and device appearance changes apply only in System. Denied persistence is visibly marked “Not saved” with a tab-local choice; invalid saved values visibly use System until explicitly replaced. The self-hosted, parser-blocking `theme-init.js` sets the initial appearance before the app bundle without changing the server CSP. Semantic color tokens cover controls, statuses, highlights, popovers and modal surfaces; theme changes do not remount the app or submit actions.
- Archive starts with every authorized source HEAD, including unindexed sources. Its compact table has no redundant page heading. Every visible column sorts globally through `ArchiveSort`; LastTimestamp Desc is the default even for text queries, with the server UUID tie-breaker and NULLS LAST. Each request asks for 50 rows (contract maximum 100); opaque cursors have no authority and pages are live, not a frozen corpus.
- Cmd/Ctrl K focuses the expression editor. AND, OR, NOT, adjacency, parentheses and braces follow the server grammar. Search mode is a global expression directive, not separate buttons: `(A OR B) mode:lexical` is valid; `A OR B mode:lexical` is not. Default Hybrid and metadata/empty browsing do not invoke models without a text operand. Quick filters conjoin the entire body while keeping a quote/escape/group-aware global mode outside it. Quick-filter values are explicitly **loaded values**, not archive-wide facets. The controlled editor separately requests provider-free, authorized-universe `ExpressionHints`: one in flight plus debounced latest draft/caret/target; stale owner/connection/security epochs cannot expose a popup. Server replacement ranges and scalar-safe UTF-16 insertions preserve all outside text. Arrow keys/Enter accept into the draft only, Escape dismisses, Tab remains normal, and IME Enter never submits. Accepting a hint does not run Archive/Search or any provider work. The server remains authoritative for fields, Boolean semantics and errors.
- The small Search syntax popover explains literal lexical matching, semantic bounded sets, Hybrid's unbounded exact lexical union, and bounded-NOT/candidate-domain caveats. `annChunkLimitPerOperand` is a per-operand published **chunk** budget before session deduplication, never a row cap. Archive totals remain exact under those defined candidate sets and retain i64 precision. Unavailable semantic search returns an error; no lexical fallback is hidden.
- Infinite lists append stable IDs and reject superseded successes/rejections. A refresh atomically refetches the loaded page chain; same-identity poll tokens coalesce behind in-flight work instead of starving long chains. Every completed chain immediately removes old IDs absent from its newly authorized result and updates common values in place. Only arrivals/order changes wait behind a local explicit update control, so polling does not prepend while someone reads. The latest successful read replaces pending candidates; errors, identity/generation changes and invalidation clear both visible and pending bodies. Surviving row/pane anchors preserve the viewport across removals. Query/sort/account changes reset the chain.
- A row click or its native title button (Enter/Space) opens a 90vw × 90vh modal. Native modal isolation plus explicit Tab wrapping, Escape/backdrop close, initial/returned focus and body-scroll restoration are tested on desktop and mobile. The left passage list and right original-message pane scroll independently; mobile uses a stacked two-pane fallback. Passage selection scrolls only the right pane, never the background or a polling refresh.
- Archive rows separate HEAD metadata, published view and representative matched view. A modal initially opens matchedView, otherwise publishedView, otherwise archive-only HEAD. Boolean text operands may match different revisions; the chosen view is not an explanation of every term. Every session/annotation/message/locator read retains the same `ContentView(revision,generationId)`; raw explicitly requests its revision. Mismatched pins fail closed. The UI shows viewed revision, HEAD/index counters and lag separately. Explicit latest-HEAD access chooses an archive-only pin with no annotations; switching the whole view clears prior messages, spans and raw content together. Reconnect reauthorizes and can choose the fresh row pin. Independently refreshed Archive and session HEAD observations contribute to a numeric high-water mark within the same authorized principal/source/security epoch; late older snapshots cannot downgrade it. This never orders publication UUIDs or changes the viewed pin automatically.
- Passage pages and message windows contain 40 items. Passage and message scrolling is automatic; message windows also load earlier pages after a direct locator jump. `LocateMessage` supplies the authorized zero-based position, so there is no scan-through-all-pages or 10,000-message seek cap. Every explicit passage selection cancels an older locator, including selection of an already-loaded target. UTF-8 highlighting preserves literal source text; long messages expand explicitly.
- Activity is owner-only, not group-shared. Two dense, independently infinite tables use all 22 collector and 15 job server sort fields; Actions is not sortable. Defaults are CollectorId Asc and job LastTimestamp Desc with ascending identity ties and nulls last. Expressions, sort, scope and collector changes reset the corresponding cursor chain; late old-cursor replies cannot cross it. Filtered matching counts remain separate from unfiltered owner totals and the `allCollectors` universe.
- Activity editors search only whitelisted metadata, never messages, raw snapshots, ANN or model inference. Every mode directive is rejected, including nested directives. Quick filters AND the entire Boolean body with an escaped literal clause. Job metadata and source activity belong to the job revision; its compact `(revision,null)` pin is not current-HEAD metadata or an invented job creation time. The source model and index-profile hash are distinct. No per-row GetSession is needed.
- Collector rows show report-less namespaces as unknown, actual server received time and freshness, all Current/Historical counts and Running lease subsets. Compact Details retain per-run discovery/upload counters. Job rows distinguish superseded revision, obsolete profile and both, prior-attempt reasons, attempts, unknown totals and active/expired/unleased leases. HEADs without a target job are not Queued; Complete job state is not proof of publication. A browser socket, Idle, zero failures or processed windows does not establish health, completion or no prior retries. Only a supplied retryable Current Failed row gets an individual indexing retry; historical rows are not actionable.
- The compact “Retry all current failed” owner-summary action retains the accessible name “Retry all current failed indexing jobs”, visible scope/disabled reasons and keyboard-accessible safety help. Totals and the bounded-text preview use the full summary width rather than a reserved side column. It previews all eligible owner jobs, independently of both table filters, collector and Current/History scope. The explicit confirmation binds the target profile and opaque selection hash. Cancel performs no mutation; zero current failures disables the action even with historical failures. Conflict requires a fresh preview and renewed confirmation, never automatic Apply. Typed result counts describe the apply-time pre-action population, not current live totals. Historical and non-failed jobs remain untouched. No administrator authority is inferred. Owner reprocessing is a separate, explicit preview/confirmation workflow below.
- The conversation panel reads logical `GetPassages` metadata in pages of 40, with summary/tags, exact start/end normalized message positions and UTF-8 byte offsets, source bytes, span count and retrieval-piece count. A→B→A is three contiguous problem passages, including boundaries within a message. Selecting one uses the existing pinned locator/source pane; its spans have separate 40-entry previous/next pages. No giant concatenated passage or invented source separator is displayed. `LegacyAnnotations` alone is labeled legacy and reads the retained `GetChunks` flow. Unknown/unverified metadata errors offer “Passage metadata unavailable; existing annotations remain readable” and an explicit annotations fallback, never invented extents.
- Activity's expandable Model usage and indexing settings panel polls only while open, at most one request in flight, scheduling the next check after settlement. Exactly Annotation, DocumentEmbedding, QueryEmbedding and McpTest rows show provider-reported **completed-call** rates, known i64 tokens, reported/unknown call counts, actual coverage/window bounds/sample age and local in-flight requests. Unknown, zero and embedding N/A remain distinct; reasoning is a subset of output, never added. The server's roughly 9.9–10s recent bucket/shorter startup coverage is disclosed, not replaced with client timing. Annotation sessions, embedding requests and embedding batch size are read-only operator settings.
- “Preview reprocessing all my HEADs” covers all the signed-in owner's non-tombstone HEADs independently of expressions/collector/scope. A fresh signed selection and unchecked explicit confirmation bind the target profile. Existing publications/raw/revisions/history remain readable until atomic replacement; apply-time queued counts and empty queues are not publication completion. A changed selection requires a fresh preview and renewed confirmation. Typed `OwnerReindexed` results must match action ID/target and valid exact counts; malformed replies remain uncertain with original invocation ID/payload. Only owner/epoch-bound Receipt evidence can resolve earlier uncertainty through a stored terminal conflict, never direct Apply Conflict or an absent receipt.
- The `mcp` tab is a fresh-prompt, cost-bearing tester backed by the actual server catalog, with model/revision/output/reasoning policy, all declared limits and dynamic tool definitions shown as plain text. Every explicit Run gets a fresh catalog and random run ID; Start is sent once with transient delivery uncertainty, never Auth receipt recovery or automatic model/Start replay. Original owner-scoped IDs/controls survive navigation in tab memory; unknown execution blocks a new Start until Read observes it or the user explicitly acknowledges uncertain cost and clears. Each Start carries only its fresh prompt (scalar UTF-8, at most 16KiB), never prior traces/history. Short bounded Reads assemble full multipart tool arguments/results/response text across pages using the last **returned event**, not whole-run `lastSequence`, as cursor. Generated-codec byte/event bounds fail explicitly rather than truncate. Cancellation cannot recall data or prove provider stop/zero cost. Terminal traces continue authorized polling across navigation and erase on connection/security/account/authority changes or server expiry; no private tester state is persisted or logged.
- Access preserves Issued/StaticConfig metadata, named mint/revoke and every group create/invite/accept/remove/leave/delete action. Static tokens are configuration-managed/read-only and reveal no secret. Joining explicitly acknowledges sharing all eligible existing/future sessions with current/future members. Token/group APIs return their complete lists and expose no manual pagination controls.
- Token secrets are shown once in component memory and clear on connection/authorization invalidation. Uncertain writes remain account-bound in the top-level controller; they are never automatically replayed. Receipt lookup precedes explicit same-ID/payload retry, and a committed mint with a lost secret requires revoke/remint. A delivered bulk reply with the wrong type, inner request ID or target profile is unknown, not proof of refusal, and blocks another write pending Receipt. A direct conflict cannot end pre-existing uncertainty: only an owner/epoch-matched Receipt proving the new Apply's durable terminal conflict can do so. Typed retry results clear on invalidation/account change. Logout keeps its existing uncertainty mechanism.
- Original source/raw records are literal React text: no transcript HTML, remote images or source links execute. Raw requires the independent Raw scope. Draft/submitted expression/selection IDs are account-bound; explicit logout or an observed different identity clears them before any new-session RPC. Same-user reconnect may retain those private request identities, never previously authorized result bodies.

The dashboard negotiates **only 1.4** before issuing Archive/Activity operations. Server-side 1.0/1.1/1.2/1.3 compatibility remains separate, not a client fallback. External permission changes are detected on the next authorized read/poll (Archive/source every 20 seconds; Activity every 4 seconds), not through an invented permission-change push stream. Successful list shrink also revokes the excluded row's bound modal immediately, even without a forbidden response.

## Transport / resilient-ws-ui checklist

`src/transport/manager.ts` is independent of React, browser globals and wire DTOs. Socket factory, protocol adapter, scheduler/clock, nonce source, random source and lifecycle source are injected. `baboon.ts` supplies the real generated codec adapter; each socket gets its own Hello/ping correlation state.

Implemented:

- NEW / ALIVE / STALE / DEAD; ALIVE requires accepted version negotiation and a matched application pong. The v1 wire contract carries a nonce but no timestamp: the adapter correlates the response's envelope ID and nonce to its locally recorded send time.
- Per-nonce pong deadlines, connect timeout with native `readyState` check, bounded handshake timeout, read/request deadlines, explicit uncertain mutation outcomes, and superseded-socket/request-generation guards.
- Immediate overlapping replacement during stale grace, maximum three live sockets; late-pong recovery supersedes the replacement. Stale grace timers cannot expire a later stale period. Lifecycle verification cannot fork heartbeat chains.
- Full jitter over `[0, min(cap, base × 2^attempt)]`, capped exponential delay, eight retries, attempt reset only on ALIVE, then STOPPED/manual retry. Hidden retries defer without consuming attempts.
- Permanent protocol/data/size/TLS close codes and observable 4400/4401/4406 application closes stop. Typed unauthorized/version/protocol failures stop even without a pending request. `forbidden` is a per-request denial.
- Timer-gap detection, short-gap verification, proactive long-resume replacement, visibility/online/offline/network-change/freeze/resume/pagehide/pageshow wiring, BFCache socket closure/restore, destroyed reentry guard, and timer/listener cleanup.
- One fixed, text-plus-symbol/ring health widget derived from manager stats; countdown budgets, event-driven updates plus ~10 Hz requestAnimationFrame, title state, active/background pool styling, RTT windows, heartbeat deadline-miss rate, retry details and bounded timestamped event log.

Explicit boundaries / mitigations:

1. Main-thread timers can be throttled/frozen in hidden tabs. There is no heartbeat worker; visibility/resume/timer-gap checks replace and reauthorize instead of promising continuous background liveness.
2. Reconnection creates a fresh logical session. Whole authorized snapshots reload; there is no durable push history or mutation replay.
3. Server heartbeat scheduling/nonce lookback and Scala/native behavior belong to the server lane. The client answers server Ping with the **same envelope ID and nonce**, separately from its own heartbeats. Client tests cannot prove server scheduling correctness.
4. Browser tests dispatch resume/BFCache lifecycle events and the fake clock simulates timer pauses. These verify recovery paths, not a real OS suspension or browser BFCache eligibility.
5. The WebSocket fixture is controllable browser communication, not an actual Scala server. The integrated Scala/PostgreSQL/native browser gate remains separate.

## Tests

`npm test` runs cheap behavioral tests for protocol/codecs, connection lifecycle, UTF-8 spans, immutable view identity, exact progress, separate Archive/global-mode and Activity/no-mode expression composition, typed bulk-result verification, authorized infinite-list reconciliation and theme validation/device/persistence policy. Theme behavior runs through one contract against a manual storage/device dummy and actual browser storage/media/events. The generated 1.0→1.1→1.2→1.3→1.4 evolution chain remains covered.

`npm run test:browser` is the standard complete browser gate. It runs:

1. `tests-browser/run.mjs`: all 22 retained browser scenario groups, adapted from cards/manual pages to table/modal/infinite interactions, plus SSR loading-state coverage. Includes account/logout boundaries, collector phases/large i64s, source pinning and latest archive access, all mismatch-denial cases, 205 passages, literal/UTF-8 text, all management mutations, uncertain writes/receipt recovery, HTTP cookie login/insecure-origin UUIDs, blackhole/restart/lifecycle and bounded transport recovery.
2. `tests-browser/ux.mjs`: retained Archive/modal/lifecycle coverage plus Activity's 155 collectors and 330 Current/Historical jobs, every typed header in both directions, four-page independent append, reset/late-cursor guards, mode-free metadata/error/no-fallback checks and job-metadata provenance denial. Bulk tests cover owner-wide preview/cancel, apply-once/untouched history, zero eligible versus 58 historical failures, exact i64s, Read/browser denials, lost reply/typed receipt, renewed conflict confirmation, durable terminal rejection proof, malformed semantic replies and account/security-epoch late results. Both HEAD arrival orderings and the later both-stale high-water counterexample retain the immutable view until explicit Latest.
3. `tests-browser/refresh-regression.mjs` (`test:refresh` also runs it directly): deferred resource/infinite lifecycle checks, coalesced polling, authorization shrink/candidate non-resurrection, responsive 90vw/90vh modal focus/body/pane behavior, and the actual 20-second Archive poll asserting retained DOM nodes and user scroll with zero unsolicited navigation. A successful list shrink then clears the excluded row and bound modal without a transport/auth error.

4. `tests-browser/theme-retry.mjs` (`test:theme`): 10 groups cover compact owner-summary geometry, the shared native-browser theme contract, pre-login/reload/device behavior, denied/invalid storage, warning-state mobile popover bounds, unchanged Archive/source DOM/pins/scroll/drafts and retry confirmation/uncertainty. Light/dark desktop (1440×900) and mobile (390×844) checks audit text/control/focus contrast and capture 32 synthetic-only view PNGs plus JSON metrics under `test-results/theme-retry/`. A production build is also served with the unchanged server CSP, with the app bundle initially held to check actual first paint.

5. `tests-browser/goal50.mjs` (`test:goal50`): 34 additional actual Chromium groups cover controlled completion Unicode/midtoken/escapes/IME/stale responses/scope/epoch/no-keystroke-search, usage applicability/coalescing/i64s, contiguous logical passages and bounded span pages, unknown-profile fallback/ACL shrink, owner-wide >1000 HEAD preview/confirmation and receipt finality, and the fresh-catalog transient MCP tester's full multipart traces/no replay/navigation/authority/error boundaries. Expanded Activity usage/owner-preview states additionally check 320/390px reflow, tablet/desktop sizing, internal table scrolling, contrast and synthetic screenshots at 1×/2× device scale (not a claim of actual browser-zoom execution). Immediate Start/Complete snapshots retain the freshly validated MCP catalog while existing authority-denial fences remain covered. The original 66 browser groups are retained; native-server/provider behavior remains a separate integration gate.

Fixtures use synthetic content and generated WebSocket codecs; they are not a real Scala/PostgreSQL server. The separate native-server integration gate remains necessary. Only isolated synthetic browser fixtures produce screenshots; no native/private session is captured. Ignored `test-results/` retains those synthetic PNGs, metrics and sanitized logs; never capture private source content.
