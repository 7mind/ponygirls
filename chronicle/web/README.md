# Chronicle dashboard

React / TypeScript / Vite. Production contains no fixtures, external assets, fonts, uploads, or browser credential storage. All HTTP and WebSocket operations use the generated Baboon v1.9 classes and JSON codecs in `../generated/typescript/`; generated files are not maintained here.

## Build and verify

Node 24 and npm 11; exact dependency versions are locked in `package-lock.json`.

```bash
npm ci
npm test
npm run typecheck
npm run build
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 \
PLAYWRIGHT_BROWSERS_PATH=/path/to/playwright-1.64.1-browsers \
  npm run test:browser
```

The provisioned development browser directory is `/nix/store/3jc1mc38kwqi6vqzns8z1nqq70affw5k-playwright-browsers`. Tests never download browsers. `npm test` uses Node's experimental TypeScript transformation for generated enums, plus a test-only resolver for the generator's `.js` imports. Production uses Vite's TypeScript compilation.

Serve `dist/` on the **same origin** as `/api/login`, `/api/ws`, and the remaining server API. TLS and the server's exact Origin, session-cookie, and CSRF policies are required in deployment. The dashboard has no cross-origin/token configuration. Vite caches are source-local under ignored `.cache/vite`, including when an identical pinned dependency tree is shared read-only. `npm run dev` starts Vite on loopback; a local same-origin API reverse proxy is needed to use a real server. The browser fixture instead serves a separate, test-only entry through Vite.

## Interface

Archive, Search and Activity's Collectors and Jobs lists are full-bleed on the surface with the shared responsive gutter (`--gutter`: 24px desktop, 16px tablet, 12px mobile) and no redundant page headings; Access, MCP and Activity's Model usage and Maintenance are document-like pages (title and short description) in a column of at most 1200px on the canvas. Navigation identifies the active view. Optional reference belongs in contextual help, while action labels, confirmations, errors and uncertain-outcome recovery remain visible where needed.

- Search uses the same expression editor, authorized completion and full server-parsed Archive DSL, including global `mode:` directives, every metadata field and OR/NOT/groups. It retains explicit Enter/Search submission rather than Archive's live debounce. Source cards include unindexed HEADs and independently pinned literal/semantic representatives; metadata/negative-only matches need not have a message excerpt. Counts are exact i64 values under the reported Archive candidate-set semantics; per-operand ANN chunk bounds are not row caps. Cursor replacement pages remain live. See [Shared Archive and Search expressions](../docs/drafts/20261031-shared-search-expressions.md) for behavior and verification boundaries. MCP's separate structured/websearch contract is unchanged.

- Theme settings are available before sign-in: System (default), Light or Dark. Only the non-secret `chronicle.theme.preference` value is persisted; cross-tab changes synchronize and device appearance changes apply only in System. Denied persistence is visibly marked “Not saved” with a tab-local choice; invalid saved values visibly use System until explicitly replaced. The self-hosted, parser-blocking `theme-init.js` sets the initial appearance before the app bundle without changing the server CSP. Semantic color tokens cover controls, statuses, highlights, popovers and modal surfaces; theme changes do not remount the app or submit actions.
- Archive starts with every authorized source HEAD, including unindexed sources. Its compact table has no redundant page heading. Every visible column sorts globally through `ArchiveSort`, with the server UUID tie-breaker and NULLS LAST. The remembered column tuple starts as LastTimestamp Desc and `preferRelevance` starts true: the server orders by relevance only when that preference is set and the expression has positive text, and reports the result in `relevanceOrdered`. Empty, metadata-only, mode-only and negative-only expressions keep the column tuple. A header click selects its column order and clears the preference atomically; the `Result order` toggle (Relevance | the remembered column, shown for text queries and while a manual order replaces relevance) restores or clears the preference without discarding the tuple. Both survive text, mode, refresh, paging, tab remounts and same-owner reconnects; sign-out, expiry and owner changes reset them. Header `aria-sort` follows the current result's `relevanceOrdered`, not the preference. A reply whose `relevanceOrdered` is not a boolean is a protocol error. Each request asks for 50 rows (contract maximum 100); opaque cursors have no authority and pages are live, not a frozen corpus.
- Cmd/Ctrl K focuses the expression editor. AND, OR, NOT, adjacency, parentheses and braces follow the server grammar. Search mode is a global expression directive, not separate buttons: `(A OR B) mode:lexical` is valid; `A OR B mode:lexical` is not. Default Hybrid and metadata/empty browsing do not invoke models without a text operand. Inline field shortcuts and quoted presets conjoin the entire body while keeping a quote/escape/group-aware global mode outside it. They edit the draft and restore input focus/caret; complete presets follow Archive's ordinary live debounce, while unfinished field prefixes remain drafts. Value completion uses the authorized server path, not an exhaustive loaded-row facet list. The in-field clear control resets both the draft and applied search to empty without changing sort; Escape first dismisses suggestions, then a subsequent Escape resets the search. IME composition withholds automatic and form execution; explicit clear remains immediate, including during composition. The controlled editor separately requests provider-free, authorized-universe `ExpressionHints`: one in flight plus debounced latest draft/caret/target; stale owner/connection/security epochs cannot expose a popup. Server replacement ranges and scalar-safe UTF-16 insertions preserve all outside text. Arrow keys select and Enter accepts into the draft only, Escape dismisses suggestions, Tab remains normal, and IME Enter never submits. Accepting a hint does not directly submit; a structurally complete insertion follows the ordinary live debounce. Hint requests themselves never invoke models. The server remains authoritative for fields, Boolean semantics and errors.
- Archive applies a structurally complete draft after 350ms without Search. Draft, applied expression and displayed results remain distinct; incomplete quotes, escapes, groups, Boolean operands and field values are held, not silently repaired. Enter/Search flushes the original draft for authoritative server diagnostics, including a structurally incomplete draft outside composition. Same-expression Search is an explicit refresh; clear applies empty immediately without a second timer submission. One App-owned lane admits at most one unsettled Archive client RPC and one latest replaceable unsent intent across query/sort/refresh/edge changes and tab remounts. Superseded reads cannot replace current rows; queued refresh folds into the latest unsent read. This is not provider cancellation: client timeout/disconnect can settle while remote work continues. Semantic/Hybrid text execution can invoke query embeddings; provider-free hints do not make execution free. Activity retains explicit Filter submission.
- Archive and Activity use compact default columns. The Archive's view-bar `Conversations table options` menu holds the column checkboxes (remembered per browser), Fit columns to width/content, Show all columns and Reset columns; the Activity views' view bars hold the same menu for their tables (`Collectors table options`, `Indexing jobs table options`). The choosers retain every optional column and its server sort. Fit to width prioritizes readable scalar columns over long conversation text; Fit to content measures styled rendered text with bounded widths. Header separators support pointer drag, Left/Right (Shift for larger steps), Home and End. Resizing does not sort or fetch source content; local widths survive polling but are not persisted. Activity disables inline pinning when resized first/Actions columns would obscure the middle. The Archive table lives in the document (no inner scroller): more columns than fit scroll the document sideways with Conversation pinned, and phone widths start with Conversation and Last activity, with their own remembered choice of every column. Conversation rows show up to three tag chips and the producer below the title; complete values and HEAD/publication provenance remain in tooltips, optional columns and the session page.
- The small Search syntax popover explains literal lexical matching, semantic bounded sets, Hybrid's unbounded exact lexical union, and bounded-NOT/candidate-domain caveats. `annChunkLimitPerOperand` is a per-operand published **chunk** budget before session deduplication, never a row cap. Archive totals remain exact under those defined candidate sets and retain i64 precision. Unavailable semantic search returns an error; no lexical fallback is hidden.
- Infinite lists append stable IDs and reject superseded successes/rejections. A refresh atomically refetches the loaded page chain; same-identity poll tokens coalesce behind in-flight work instead of starving long chains. Every completed chain immediately removes old IDs absent from its newly authorized result and updates common values in place. Only arrivals/order changes wait behind a local explicit update control, so polling does not prepend while someone reads. The latest successful read replaces pending candidates; a failed refresh, identity/generation changes and invalidation clear both visible and pending bodies, while a failed append keeps the loaded rows and offers Retry. The Archive keeps its settled chains per owner and shows one again (re-reading it) when its query returns. Surviving row/pane anchors preserve the viewport across removals. Query/sort/account changes reset the chain.
- A row click or a plain click on its title link opens the routed session page `#/session/<id>` (the link's address also works as a new tab or deep link); Back returns to the list with its loaded rows, scroll and focus. The transcript and the side pane scroll independently; phone widths stack them. Passage selection scrolls only the transcript, never the background or a polling refresh.
- Archive rows separate HEAD metadata, published view and representative matched view. The session page initially opens matchedView, otherwise publishedView, otherwise archive-only HEAD. Boolean text operands may match different revisions; the chosen view is not an explanation of every term. Every session/annotation/message/locator read retains the same `ContentView(revision,generationId)`. The dashboard offers normalized messages only; the raw-record server API is unchanged. Mismatched pins fail closed. The UI shows viewed revision, HEAD/index counters and lag separately. Explicit latest-HEAD access chooses an archive-only pin with no annotations; switching the whole view clears prior messages and spans together. Reconnect reauthorizes and can choose the fresh row pin. Independently refreshed Archive and session HEAD observations contribute to a numeric high-water mark within the same authorized principal/source/security epoch; late older snapshots cannot downgrade it. This never orders publication UUIDs or changes the viewed pin automatically.
- Passage pages and message windows contain 40 items. Passage and message scrolling is automatic; message windows also load earlier pages after a direct locator jump. `LocateMessage` supplies the authorized zero-based position, so there is no scan-through-all-pages or 10,000-message seek cap. Every explicit passage selection cancels an older locator, including selection of an already-loaded target. UTF-8 highlighting preserves literal source text; long messages expand explicitly.
- Activity is owner-only, not group-shared. Two independently infinite tables retain all 22 collector and 15 job server sort fields through the column chooser; Actions is not sortable. Defaults are CollectorId Asc and job LastTimestamp Desc with ascending identity ties and nulls last. Expressions, sort, scope and collector changes reset the corresponding cursor chain; late old-cursor replies cannot cross it. Filtered matching counts remain separate from unfiltered owner totals and the `allCollectors` universe.
- Activity editors search only whitelisted metadata, never messages, raw snapshots, ANN or model inference. Every mode directive is rejected, including nested directives. Inline field/preset shortcuts AND the entire Boolean body with a grammar-safe clause and edit only that editor's draft. Its clear control resets only that editor's applied expression; collector selection and Current/History scope remain separate. Job metadata and source activity belong to the job revision; its compact `(revision,null)` pin is not current-HEAD metadata or an invented job creation time. The source model and index-profile hash are distinct. No per-row GetSession is needed.
- Collector columns retain report-less namespaces as unknown, actual server received time/freshness, and all Current/Historical counts and Running lease subsets; less common columns remain available through Columns. Compact Details retain per-run discovery/upload counters. Job rows distinguish superseded revision, obsolete profile and both, prior-attempt reasons, attempts, unknown totals and active/expired/unleased leases. HEADs without a target job are not Queued; Complete job state is not proof of publication. A browser socket, Idle, zero failures or processed windows does not establish health, completion or no prior retries. Only a supplied retryable Current Failed row gets an individual indexing retry; historical rows are not actionable.
- The Maintenance page's “Retry all current failed” action retains the accessible name “Retry all current failed indexing jobs”, visible scope/disabled reasons and keyboard-accessible safety help; its confirmation dialog shows the exact preview populations. It previews all eligible owner jobs, independently of both table filters, collector and Current/History scope. The explicit confirmation binds the target profile and opaque selection hash. Cancel performs no mutation; zero current failures disables the action even with historical failures. Conflict requires a fresh preview and renewed confirmation, never automatic Apply. Typed result counts describe the apply-time pre-action population, not current live totals. Historical and non-failed jobs remain untouched. No administrator authority is inferred. Owner reprocessing is a separate, explicit preview/confirmation workflow below.
- The conversation panel reads logical `GetPassages` metadata in pages of 40, with summary/tags, exact start/end normalized message positions and UTF-8 byte offsets, source bytes, span count and retrieval-piece count. A→B→A is three contiguous problem passages, including boundaries within a message. Selecting one uses the existing pinned locator/source pane; its spans have separate 40-entry previous/next pages. No giant concatenated passage or invented source separator is displayed. Only `ContextAwareProblems` and `Unindexed` pages render; any other format and unknown or unverified metadata show “Problem metadata unavailable. Original source remains readable; no legacy annotation fallback is used.”, never invented extents.
- Activity's Model usage sub-view polls only while it (or the Overview) is shown, at most one request in flight, scheduling the next check after settlement. Exactly Annotation, DocumentEmbedding, QueryEmbedding and McpTest rows show provider-reported **completed-call** rates, known i64 tokens, reported/unknown call counts, actual coverage/window bounds/sample age and local in-flight requests. Unknown, zero and embedding N/A remain distinct; reasoning is a subset of output, never added. The server's roughly 9.9–10s recent bucket/shorter startup coverage is disclosed, not replaced with client timing. Annotation sessions, embedding requests and embedding batch size are read-only operator settings.
- The Maintenance page's archive rebuild (“Rebuild archive index”) previews and covers all the signed-in owner's non-tombstone HEADs independently of expressions/collector/scope. A fresh signed selection and unchecked explicit confirmation bind the target profile. Existing publications/raw/revisions/history remain readable until atomic replacement; apply-time queued counts and empty queues are not publication completion. A changed selection requires a fresh preview and renewed confirmation. Typed `OwnerReindexed` results must match action ID/target and valid exact counts; malformed replies remain uncertain with original invocation ID/payload. Only owner/epoch-bound Receipt evidence can resolve earlier uncertainty through a stored terminal conflict, never direct Apply Conflict or an absent receipt.
- The `mcp` tab is a fresh-prompt, cost-bearing tester backed by the actual server catalog, with model/revision/output/reasoning policy, all declared limits and dynamic tool definitions shown as plain text. Every explicit Run gets a fresh catalog and random run ID; Start is sent once with transient delivery uncertainty, never Auth receipt recovery or automatic model/Start replay. Original owner-scoped IDs/controls survive navigation in tab memory; unknown execution blocks a new Start until Read observes it or the user explicitly acknowledges uncertain cost and clears. Each Start carries only its fresh prompt (scalar UTF-8, at most 16KiB), never prior traces/history. Short bounded Reads assemble full multipart tool arguments/results/response text across pages using the last **returned event**, not whole-run `lastSequence`, as cursor. Generated-codec byte/event bounds fail explicitly rather than truncate. Cancellation cannot recall data or prove provider stop/zero cost. Terminal traces continue authorized polling across navigation and erase on connection/security/account/authority changes or server expiry; no private tester state is persisted or logged.
- Access preserves Issued/StaticConfig metadata, named mint/revoke and every group create/invite/accept/remove/leave/delete action. Static tokens are configuration-managed/read-only and reveal no secret. Joining explicitly acknowledges sharing all eligible existing/future sessions with current/future members. Token/group APIs return their complete lists and expose no manual pagination controls.
- Token secrets are shown once in component memory and clear on connection/authorization invalidation. Uncertain writes remain account-bound in the top-level controller; they are never automatically replayed. Receipt lookup precedes explicit same-ID/payload retry, and a committed mint with a lost secret requires revoke/remint. A delivered bulk reply with the wrong type, inner request ID or target profile is unknown, not proof of refusal, and blocks another write pending Receipt. A direct conflict cannot end pre-existing uncertainty: only an owner/epoch-matched Receipt proving the new Apply's durable terminal conflict can do so. Typed retry results clear on invalidation/account change. Logout keeps its existing uncertainty mechanism.
- Conversation source uses monospace text with textual role labels and theme-aware role accents. Lightweight Markdown supports headings, emphasis, inline code, quotes, lists and fenced code blocks, without executing HTML, images or links. Copy message preserves the complete original text; Copy code preserves the code body including whitespace/newlines. Source text switches back to the unchanged transcript. Annotation/search highlights always display unchanged source text, preserving UTF-8 byte ranges even across Markdown delimiters. Clipboard failure is explicit. Messages above 20,000 characters or 500 lines explicitly use source text instead of expanding a large formatted DOM; copying still retains the complete text. Raw-record mode and its permission warnings are absent from the dashboard; the separate authorized server API is unchanged.
- Routine mutation success uses dismissible transient toasts rather than taking up page space. Errors and uncertain-write receipt/retry controls stay actionable; rebuild progress and typed bulk-result evidence remain persistent.
- A session opens as the routed page `#/session/<id>?rev=&gen=&at=&find=&span=&pane=&passage=` (Archive rows and titles, Search titles, hits and "Open at first match"; Back returns to the list with its rows, scroll and focus). A Search link's `span` (UTF-8 byte range of the match in the `at` message) lands on the match: the message unfolds, the bytes are highlighted and the landing marker takes the focus. Any authority denial of a session read (session, messages, passages, locator, Find, Related) clears the transcript, outline and Find into a notice with Retry. Its header carries Back, the meta line with the parent list's link, Find, the side pane toggle and a menu (Recheck source, Go to latest archive, Provenance and metadata); the side pane holds Outline, Find, Related and Info (provenance). Literal Find is a docked bar; it searches the full selected revision, including unloaded messages, without model calls, and retains revision/authority fences and keyboard navigation. A malformed `rev`/`gen` is an invalid address, never a default view. Draft/submitted expression/selection IDs are account-bound; explicit logout, terminal authentication expiry or an observed different identity clears them before any new-session RPC, including sign-in as the same owner after expiry. A nonterminal same-user network reconnect may retain those private request identities, never previously authorized result bodies.

The dashboard negotiates **only the current API version (1.9.0)** before issuing Archive/Activity operations; older and future versions are rejected, with no client fallback. External permission changes are detected on the next authorized read/poll (Archive/source every 20 seconds; Activity every 4 seconds), not through an invented permission-change push stream. Successful list shrink also clears the session page opened from the excluded row immediately, even without a forbidden response. Source denials cross views as `chronicle:source-unavailable` document notices (`src/source-authority.ts`): the session page's denials clear Search results of that source, Search's denials clear the open session when they concern its pin.

## Recorded yolo profiles

Conversation provenance and Activity job Details show **Recorded yolo profile**, derived from the selected revision's exact `source.discoveryRootId` claim `yolo:<name>` (launcher-valid names only). Native/default and unrecognized roots show “not recorded”; no title/tag/path inference is performed. Archive and Activity job field shortcuts and authorized value hints expose `yolo-profile:`. Values are exact and case-sensitive; existing hint prefixes remain case-insensitive. Activity `profile:` still means the annotation/index policy hash. Historical jobs retain their own revision's recorded value.

This is a recorded storage-root claim, not authenticated host/launch provenance: clients may supply root IDs and sessions can be copied between profiles. Existing archives need no metadata rewrite or re-ingestion. The attribute does not change ordinary text search, selected-history Find, source identity or collector admission. MCP `search_sessions` has its separate structured-filter/websearch contract and does not accept this expression field; inspect recorded source claims with `get_session`.

## Transport / resilient-ws-ui checklist

`src/transport/manager.ts` is independent of React, browser globals and wire DTOs. Socket factory, protocol adapter, scheduler/clock, nonce source, random source and lifecycle source are injected. `baboon.ts` supplies the real generated codec adapter; each socket gets its own Hello/ping correlation state.

Implemented:

- NEW / ALIVE / STALE / DEAD; ALIVE requires accepted version negotiation and a matched application pong. The v1 wire contract carries a nonce but no timestamp: the adapter correlates the response's envelope ID and nonce to its locally recorded send time.
- Per-nonce pong deadlines, connect timeout with native `readyState` check, bounded handshake timeout, read/request deadlines, explicit uncertain mutation outcomes, and superseded-socket/request-generation guards.
- Immediate overlapping replacement during stale grace, maximum three live sockets; late-pong recovery supersedes the replacement. Stale grace timers cannot expire a later stale period. Lifecycle verification cannot fork heartbeat chains.
- Full jitter over `[0, min(cap, base × 2^attempt)]`, capped exponential delay, eight retries, attempt reset only on ALIVE, then STOPPED/manual retry. Hidden retries defer without consuming attempts.
- Permanent protocol/data/size/TLS close codes and observable 4400/4401/4406 application closes stop. Typed unauthorized/version/protocol failures stop even without a pending request. `forbidden` is a per-request denial.
- Timer-gap detection, short-gap verification, proactive long-resume replacement, visibility/online/offline/network-change/freeze/resume/pagehide/pageshow wiring, BFCache socket closure/restore, destroyed reentry guard, and timer/listener cleanup.
- One fixed, text-plus-symbol/ring health widget derived from manager stats; countdown budgets, event-driven updates plus ~10 Hz requestAnimationFrame, title state, active/background pool styling, RTT windows, heartbeat deadline-miss rate, retry details and bounded timestamped event log.

Explicit boundaries / mitigations:

1. Main-thread timers can be throttled/frozen in hidden tabs. There is no heartbeat worker; visibility/resume/timer-gap checks replace and reauthorize instead of promising continuous background liveness.
2. Reconnection creates a fresh logical socket session. Whole authorized snapshots reload; there is no durable push history or mutation replay.
3. Server heartbeat scheduling/nonce lookback and Scala/native behavior belong to the server lane. The client answers server Ping with the **same envelope ID and nonce**, separately from its own heartbeats. Client tests cannot prove server scheduling correctness.
4. Browser tests dispatch resume/BFCache lifecycle events and the fake clock simulates timer pauses. These verify recovery paths, not a real OS suspension or browser BFCache eligibility.
5. The WebSocket fixture is controllable browser communication, not an actual Scala server. The integrated Scala/PostgreSQL/native browser gate remains separate.
