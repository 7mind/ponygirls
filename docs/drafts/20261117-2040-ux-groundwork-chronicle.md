# Chronicle dashboard — UX groundwork (capture, inventory, token census, defects)

Base commit f153d1ae. Analysis only: no product code, test or Nix change. Harness: `chronicle/web/ui-capture/`.
Screenshots + `index.md` + DOM dumps: `/home/pavel/work/flakes/ponygirls/.local/overhaul-20261117/ux/chronicle/before/` (153 PNG, 24 MB, git-ignored scratch).

**Evidence conventions.** *Measured* = produced by the harness or `token-census.mjs` (file named). *Code* = read from source (file:line). *Inferred* = my reading, not run.
Load at the final run: `uptime` 21:06Z load average 137.1 / 150.2 / 155.7 on 128 cores; harness wall time 170 s (measured, `index.md`).

**Three limits you must know before using the numbers**
1. **Scripted server, not the real Chronicle server.** The brief says the browser tests "start a real server"; I found none that does — every `tests-browser/*.mjs` drives the real React app through `ChronicleFixture` (in-page `routeWebSocket` + `page.route`). The harness reuses that fixture family (subclass `CaptureFixture`) with 420 archive rows, 36 collectors, ~290 jobs, 6 transcript templates. A real Scala server + PostgreSQL + providers was out of reach under load ~150 and would not change DOM/CSS findings; ranking, latency and real data shape are not represented.
2. **I could not look at the screenshots.** The `read` tool returns raw PNG bytes to me, and a reader subagent probe also answered "CANNOT SEE IMAGE". Captures were verified programmatically instead: each shot follows an explicit DOM wait, and `Recorder` decodes every PNG and flags near-uniform images (0 of 153 flagged; the sparsest legitimate one is the update-required state, dominant colour 97.6 %). Claims below rest on DOM metrics (`inventory/*.json`) and code, not on visual impression. A human or image-capable agent should skim `index.md` + the PNGs before the design lead relies on any "looks" statement.
3. Native `window.confirm` dialogs cannot appear in screenshots (token revoke, group delete); their text is in `inventory/account-native-confirms.json`.

## 1 How to run the harness

```bash
nix develop .#chronicle --command bash -c 'cd chronicle/web && npm ci --offline \
  && node --experimental-transform-types --import ./tests/resolve-generated.mjs \
       ui-capture/capture.mjs <output-dir> [scenario-regex]'
```
Prerequisites: pinned dev shell (Node 24.22.2, Playwright 1.64.1 browsers via `PLAYWRIGHT_BROWSERS_PATH`); `npm ci` only on a fresh tree (offline succeeded here). Vite on an ephemeral 127.0.0.1 port, headless Chromium, everything closed on exit; nothing is referenced from `package.json`, Nix or CI. Run it in the foreground (a backgrounded run was killed when my tool call ended). Vite prints `EMFILE` file-watcher noise when inotify is exhausted; harmless (the HOST-NOTES shim was not used). Details and "how to add a capture": `chronicle/web/ui-capture/README.md`.

Other facts
- **Expression editor** (Archive + Search, `ExpressionEditor.tsx`): combobox + clear + `⌘/Ctrl K` hint + Search button, 12 field chips + 5 presets, syntax popover. Archive applies live after 350 ms (`Archive.tsx:21`), Search needs explicit submit; Activity has two separate `MetadataEditor`s with "Filter".
- **Popovers**: custom `Popover.tsx` (native `popover` attribute, JS positioning, 270–560 px widths, bottom sheets ≤640 px). Session uses custom `Dialog.tsx` (native `<dialog>` + manual focus trap + body lock). **Toasts**: `MutationToast`, 6 s, pause on hover/focus; errors/uncertain states stay inline.
- **Theme**: System/Light/Dark popover; `theme-init.js` sets `data-theme` before the bundle; 70 colour custom properties per theme (`theme.css`).
- **`shared/account-web` embedding.** `index.html` loads `/account.css` and `/account.js` outside the Vite bundle (plugin in `vite.config.ts` serves them in dev and emits them at build; the server special-cases both paths, `Http.scala:156`). `account.js` is delegated: any element with `data-account-settings data-account-user-id` (masthead "Settings", Access "Open token settings") opens a dialog built **imperatively** with `document.createElement` and appended to `body`; the login `<form data-account-login>` rendered by `App.tsx:31` is submitted by it. React coupling: `account:invalidate` (dispatched by `App.tsx` on logout/invalidation) and `account:changed` (dialog → app → `connection.retry()`). Styling: `account.css` is self-contained — 6 `--account-*` variables with light/dark values, `rem` units (1 rem = 14 px since `:root{font-size:14px}`), `font: 1rem/1.5 system-ui` (app uses Inter), radius .65 rem, shadow `0 1rem 4rem #0004`, focus `#5278e4`, 5 colour literals; it follows the app theme only through `html[data-theme=…]` / `prefers-color-scheme`. Box: `min(42rem, 100vw-1.5rem)` = 588 px, `max-height: 100dvh - 1.5rem`, `overflow:auto`; heading and Close button are not sticky (measured scrollHeight 5887 vs 877 with 32 tokens, `account-dialog-long-list.json`).

## 6 Open questions (with recommendations)

1. **Real-server captures.** Should the groundwork also run against the real Scala server + PostgreSQL for realistic ranking and excerpts? *Recommendation:* not for the design phase; add later only for Search/excerpt realism.
2. **Visual review.** No agent here can see PNGs. *Recommendation:* a human or image-capable agent skims `index.md` first; every §4 claim has a DOM/code anchor but "looks" were not judged.
3. **Routing as a prerequisite.** G1/A2/A3/Q4 stem from state-in-component. *Recommendation:* decide the URL structure (tab, expression, sort, `session/<id>?rev=…&at=<message>`) before the visual spec; it decides modal vs page for sessions.
4. **Session: modal or page?** The 90vw×90vh modal is locked by `refresh-regression.mjs:137` and the body-lock code; a page view would remove S1's behind-the-backdrop contexts. *Recommendation:* routed page with the transcript as the single scroller.
5. **Account dialog ownership.** Shared by Chronicle, Haystack and Manure with its own suite. *Recommendation:* migrate it to the shared semantic tokens in one change set with all three dashboards.
6. **Search pagination semantics.** Opaque cursors cannot give stable page numbers. *Recommendation:* "load more" with an exact result counter.
7. **Fixture coupling.** `CaptureFixture` subclasses `tests-browser/{fixture,goal50-fixture,search-fixture}.mjs`; the test-triage workstream may move or delete them. *Recommendation:* keep those files stable, or move them to a shared directory when tests are overhauled.
