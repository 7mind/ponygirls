**How `shared/account-web` is embedded.** `index.html` links `/account.css` and `/account.js` (`vite-ignore`; copied verbatim by the `accountAssets` Vite plugin from `shared/account-web/`, `vite.config.ts:8-27`) — they bypass the Vite/CSS pipeline and are not themed by `styles.css`. The script installs delegated click/submit handlers: `[data-account-settings]` (rendered at `App.tsx:129` with `data-account-user-id`) opens a dynamically built `<dialog class="account-dialog">` appended to `<body>`; `form[data-account-login]` (`Login.tsx`) posts to `/api/account/v1/login`. The dashboard talks back only via DOM events (`account:invalidate`, `account:changed`, `App.tsx:40,61`). The dialog styles itself with its own `--account-*` variables, `rem` units, `system-ui` 16 px base, rounded corners (.65rem dialog / .3rem controls) and `prefers-color-scheme` (plus unused `html[data-theme]` hooks; Haystack never sets `data-theme`, grep). It is the only rounded, rem-based, 16 px component in the app.

**Navigation graph.** Login → Browse ⇄ {Inbox, Upstream, Skills, Archive} (`#/browse?q=…` / `#/inbox`) → row → Item → {Edit, Clear attention, View snapshot → Compare, Restore, links → other Item} → Back → `#/browse`. Header: brand → `#/browse`; Settings (dialog); Sign out; connection popover.

Measured on rendered pages (`dom/*.json`, text characters by computed font size): on Browse at 1440x900 **47 % of visible text is ≤ 11 px** (10 px: column headers, type badges, activity-namespace label, modified cells; 11 px: help, footer, badges), 38 % with all 569 rows; detail pages 4–33 % (long Markdown is 13 px). Ten interactive targets on the Browse page are < 24 px in one dimension (incl. 11 px-high sort buttons, 13 px-high help `<summary>`; list in `dom/08-browse-first.json`). Contrast computed from the tokens (WCAG formula, Python): text pairs ≥ 5.5:1 in both themes (muted on `--surface-muted` header 5.52 light / 6.64 dark), warning/danger/primary pairs 6.3–8.7:1; **borders vs card 1.68:1 light / 2.84:1 dark** (`--line`); account dialog border 1.53:1 light. Text contrast is not the problem; size is.

Reading the numbers: a disciplined colour system (variables only) but no type scale (12 sizes), no spacing scale (21 values; 9/10/12/14 px used interchangeably), a hard-coded 0 radius with 1px-border-everything boxes, and an embedded component (account dialog) from a different system (rem, radii, own palette). This is the concrete basis for "paddings, margins, colors".

## 6. Open questions (with recommendation)

1. **Scope of `shared/account-web`**: H-05/H-06/H-20/H-22 live in the shared script, so any fix changes Chronicle and Manure too. *Recommend* designing the dialog once (token bridge + behaviour fixes) and using `shared/account-web/tests/browser.mjs` plus each service's account tests as the gate.
2. **Square corners are test-enforced** (`run.mjs:547-561`). *Recommend* deciding radii first; if radii are introduced, change that case deliberately.
3. **List mechanics**: search exposes a cursor and no total (numbered pages need server work). *Recommend* keeping cursor loading with a single scroll owner and in-place live merge; confirm whether a total-count endpoint is acceptable.
4. **Live resync double-fetch (H-03)**: the first-connect reload looks unintended. *Recommend* confirming with the owner of `Live.tsx` before the redesign builds on it.
5. **Dark theme** exists only via `prefers-color-scheme`. *Recommend* deciding whether a toggle is in scope (account.css already has `html[data-theme]` hooks).
6. **Not verified**: I could not look at the screenshots (see caveats); a human or image-capable agent should skim `index.md` and a dozen key PNGs (08, 14, 50, 63, 68, 73, 96) to confirm the visual defects implied by the measurements.
