# Automatic ontology maintenance across one evolving session

## Answer and scope correction

**Qualified feasibility, not unattended reliability:** the model maintained a coherent revisable account through a compact full-session sequence, with one genuine publication failure. This tests the requested **automatic ontology maintenance and intent tagging**, not editing Human intent. Routine curation needs no per-change approval. Source messages are immutable; interpreted nodes, classifications and links change automatically, with history retained.

This is an additive correction to the framing of the [design](20261107-1817-objective-steward.md) and [snapshot pilot](20261107-2114-objective-steward-pilot.md). Empty correction-proposal arrays were not a failure of the requested workflow. The earlier snapshot evidence remains unchanged; it did not test longitudinal maintenance.

## What ran

- **`openai-codex/gpt-6.1-sol`, medium thinking**, pinned Pi1.4.0, same selection as the earlier pilot.
- One independently authored, wholly synthetic24-event session,12 successive checkpoints. Fictional packet-counter work includes a separate side objective, mistaken worker assumptions, a Human requirement revision, tests/claims with different scopes, cancellation, hypothesis retraction, aliases, handoff and genuinely unverified recovery.
- Each call receives raw growing conversation prefix and the **actual previous committed model graph**, initially empty. No pretyped host-authored objectives/claims, oracle, selectors or rationale enter the request. A fresh tool-less Agent updates each boundary; one SQLite-backed graph/history persists outside the Agent. This is not12 isolated snapshot extractions, nor proof of retention in one Agent's hidden conversational context.
- Generic prompt frozen before parent inspection of the independent narrative/oracle or any live output: SHA256 `a256334222b4c4123168c4df6fb7b667b31ecf721cc0ec3f98f93a7f2f0ce045`.
- Committed inference instrument/corpus/oracle: **`8ca4b7d96a0a4ce38d994d97df728a3413137c30`**, exported byte-for-byte into immutable Nix storage before execution.12 original admissions, no repair, replacement, provider/model fallback, semantic rerun or post-outcome oracle/prompt edits.

## Original controls and their limitations

**12 planned /12 admitted /11 published /1 failed** checkpoints. Of111 predeclared controls,106 could be evaluated at published checkpoints: **81 satisfied /25 unsatisfied**;5 at C01 unavailable. These are bounded classification/cardinality, relation, identity and forbidden-tag checks—not semantic accuracy or Human acceptance.

The original oracle and score are preserved without an adjusted or rescued score. Inspection exposes material limitations:

- Broad source-membership selectors match several distinct correct records. E05 contains implementation and completion claims; E09 both revises one requirement and reiterates unchanged ones. Cardinality bounds then misidentify granularity/citation differences as failures.
- Some identity checks demand a singleton even where the same oracle allows two matching recovery-work records. Retagging an explanation in place can also remove it from a type-specific selector; at C10 the selector instead matches a retracted hypothesis that cites the same later event. That is not observed candidate ID reassignment.
- Treating a worker-reported index inspection as a sourced claim instead of an observation is defensible provenance preservation. The oracle does not establish that the model must promote it to observation.
- Two relation checks require a direct observation-to-claim/goal edge; the candidate connects these through an intervening defect. The evidence connection exists but needs two-hop traversal.
- Three C02 continuity checks depend on the missing valid C01 publication.

The [non-blind parent qualitative review](../../scripts/objective-steward-pilot/results/session-001/semantic-review.json) records each trajectory judgment and these qualifications. All distinct node/relation contents were inspected via initial state and complete changed-record packs, with unchanged IDs inventoried; the rejected original was also inspected. This is same-family **Agent judgment, not Human gold or independent-family certification**. It was persisted before telemetry reduction.

## Reliability, instrumentation and evidence

The vocabulary violation is real. Validation prevented invalid persistence, but did not deliver an always-current graph. Failed windows expose stale/unreviewed coverage; subsequent distinct checkpoints receive the full current prefix plus only the last valid committed graph. This explicit degradation is not a retry or rescue of the failed checkpoint.

There are also representational pressures:48nodes/85links for24 compact events, overlapping composite/subtasks, and `supports` edges whose warrant strength depends on linked/source context. These may burden inspection or mislead a consumer that treats a support edge as a fulfillment certificate; no such downstream consumer or Human inspection outcome was measured.

Mechanical controls use the shared MemoryStore/real SQLite contracts and a scripted transport. Before the live run: **51 Python methods passed**,0 failures/errors/skips;17 Node tests discovered,16 passed,0 failed,1 optional remote-provider leg skipped. The genuine12-checkpoint provider run above is separate from that skip. Three later static-renderer tests establish escaping/binding/workflow behavior only; the complete code suite then passed54 Python methods and16 Node tests with the same one optional remote-provider skip. Final integrated-suite receipts are retained separately; no Chronicle/application/native-UI suite is implied.

Failures reproduced before correction and retained in the ignored task archive: public-wire tuple/list mismatch; failed-request oracle-leak bypass; truncated inventory hiding completed checkpoints; forged failed-window retained graph; extra hidden fields jointly added to snapshot/request. Corrected checks validate all retained requests, complete snapshot shape, original model-return/publication equality, failed-window retained state and causal inventory/history. These engineering checks do not validate model meaning.

After qualitative review, descriptive telemetry:12 SDK usage objects, reported totalTokens sum **88696**; per-checkpoint elapsed min12.25s, median69.43s, max113.92s, sum794.88s. SDK normalization/accounting is not independently verified billing or a quality metric. No financial cap was imposed.

A [read-only advisory](../../scripts/objective-steward-pilot/results/session-001/advisory-review.json) found no substantive support defects. Installed skills, the existing experiment draft and inert local r7 already cover the reusable procedures; no novel skill candidate was justified, saved or installed.

## What remains unknown

This compact synthetic prefix fits the context window. No long real development session, context eviction/compressed-source-only maintenance, authenticated native event feed, asynchronous branch navigation, production ontology adoption, native hotkey/UI, deployment, operational-goal mutation or actual Human inspection/repair benefit was tested. There is no second execution-goal writer.

The bounded conclusion is therefore: **automatic curation of an evolving ontology is feasible here and tracked the substantive changes; this run does not establish reliable unattended operation or a quantitative semantic-quality rate.**
