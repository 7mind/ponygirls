## 2 Method and measurement conditions

* Host shared with ~8 other agents; `uptime` 1-minute load was 148–189 on 128 cores at every measurement (per-run values in `*.uptime` next to the logs). All timings are inflated and noisy; the host was never idle. Use my seconds for ranking and for fixed real-time waits (heartbeats are load-independent), not as idle-host numbers.
* **sbt runs used the diagnostic `LD_PRELOAD` inotify shim** from `HOST-NOTES.md` (Scala suites, shared modules). Not used for Node/browser runs. Nothing depends on it in git. I also stopped the `git fsmonitor` daemon of my own worktree.
* Pinned shells: `nix develop .#chronicle` (Node 24.22.2, GraalVM 25.0.4, sbt 2.0.12, PostgreSQL 18.6). `npm ci --offline` for `haystack/`, `haystack/cli/`, and `chronicle/web/` (Playwright for `account-web`). Private `/tmp/ths*.XXXX` TMPDIRs; PostgreSQL clusters on ephemeral ports, all stopped; no live services touched.
* sbt compile output was served from the shared sbt disk cache ("cache 100%"); I verified the *tests* executed fresh: XML timestamps match the run and the tests' HTTP logs carry fresh request ids. Compile/sbt start (~20 s) is excluded from per-suite times but included in script walls.
* Native-runtime suites (`tests-current`, browser, CLI real) ran against the already-built native ELF (`nix path-info .#haystack` = `/nix/store/nd7p3wnqg3fa5cwvyz86n99qzy8wpfh3-haystack-0.1.0`, the output for this commit). I did not build a native image.
* Not run: the Nix derivations themselves (`haystack-native`, `haystack-browser`, `haystack-proxy`, `haystack-web`, `haystack-cli`) — I ran their test commands on the host with equivalent inputs. Nix-level durations are quoted from [H]. `haystack-proxy`, `backend-source`, `backend-coassembly`, `backend-runner-contract` were not run (static analysis; hist durations 0–28 s [H]).
* Commands (full env in the raw dir scripts): Scala `haystack/scripts/test-postgres-scala.sh` (RC 0, 715 tests/34 suites, wall 61.7 s); `shared/{service-runtime,service-auth,retrieval-postgres}/scripts/test-postgres.sh` and `losslessJson/testFull` (all RC 0; walls 14.4/19.9/121.2/12.4 s); `haystack/scripts/test-current.sh` with the native ELF (RC 0, 42 cases, wall 228.3 s); web unit `node --import ../scripts/register-generated.mjs --test tests/*.test.ts tests/*.test.mjs` (82 tests, 14.1 s) and `node tests-browser/browse-markup.mjs`; CLI `node --test --test-concurrency=1 tests/*.test.mjs` (58 cases, 40.9 s) and `tests/real.acceptance.mjs` against ELF+PG (12 cases, 84.1 s); browser legs timed individually (vite build 0.3 s, markup 0.9, layout 10.4, account 10.4, run 108.6, restart 13.2, quick-preview 9.2); `node shared/account-web/tests/browser.mjs` (22 cases, 7.1 s); `npm run typecheck -w web` 1.2 s.
* Taxonomy: `constructive-test-taxonomy` tags as Encapsulation-Isolation (`B`lackbox/`E`ffectual/`W`hitebox × `A`tomic/`G`roup/`Good`Communication). Purpose/Status are Behavioral/Active everywhere (no Progression tests found). The Scala contracts already follow the `dual-tests` pattern (hand-written memory dummy + PG), which is the model for the rest.
* Per-journey browser timings are noisy (e.g. "conflict preserves draft" 12.8 s); treat as load artefacts unless a real wait is visible in the code.

## 7 Risks of acting on the verdicts, and verification

* **Heartbeat parameterisation changes the production configuration surface** and the policy "preserve real deadlines" (AGENTS.md; `authority-lifetime.test.mjs:52`). Verify: keep one test pinning the default 30 s and one real-socket two-beat test at the shortened interval; run the old 62 s test once against the refactored ELF before deleting it.
* **Deleting harness tests removes fixture safety nets** (helper protocol, port ownership, "fail rather than skip" prerequisites). Verify: the wrapper (`with-service-postgres`) and Nix scripts still fail closed; mutation check — break the provisioning command and confirm the suite fails loudly.
* **Historical compat consolidation** could lose a rare quirk fixture. Verify before/after: mutate `decodeStored` limits and the loader whitespace predicate; the reduced table must still fail; keep the fixture files.
* **Dropping inventories/receipts removes the "no case silently vanished" guard.** Replace by the runner's non-zero exit on empty runs plus a `cases > 0` assertion.
* **Sharding `run.mjs`** may expose hidden shared-state coupling between journeys (shared seeded data, `searchInterceptor`). Verify: run shards in random order 10×; compare pass sets.
* **CLI in-process invocation** can differ from process behaviour (stdio, exit codes); keep process-level cases for those.
* **Timeouts**: the native check already runs at 225.7 s of a 240 s hard limit under load — do not restructure without shrinking it first.
* Overall check that nothing valuable was lost: (1) record per-case pass sets before; (2) mutation spot checks on the contracts named in `haystack/docs/port-contract-inventory.md` (CAS/replay, exact numbers, revocation after body admission, live-socket close codes, migration rollback, ACL-before-window); (3) deleted files stay recoverable in git history — cite the commit.
