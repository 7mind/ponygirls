# Where coding agents cut tool output

**A preview on first delivery and an edit to old history solve different problems.** The former bounds even a single enormous command response, but the agent may never see the middle. The latter lets the agent use the full observation first, then risks changing a prefix it has already paid to process. Neither an omission notice nor a small prompt promises that the original can be recovered. Six codebases illustrate the differences.

## Before the next model call

- **OpenAI Codex** (`7edf91b1`). For oversized plain text, [the formatter][codex-fmt] adds an estimated original token count and a line count. The [string policy][codex-cut] divides a **byte** budget between both ends, or converts an approximate token allowance to bytes at four bytes/token. It cuts at UTF-8 character boundaries; the omission marker is *outside* the retained-text budget. The [exec integration test][codex-test] inspects the mock model's next request, not the terminal: it expects `1` through `6`, a token-omission marker, and `99999` and `100000`. The formatter supplies no address for the middle. This demonstrates a model-facing preview, not exact replay or better task performance.
- **mini-SWE-agent** (`04d809ce`). The [default Jinja observation template][mini-default] keeps the return code and exception information; when `length >= 10000`, it renders the first and last 5,000 Python string characters and the count elided. At exactly 10,000 it issues the warning with *zero* elided. The [mini template][mini-template] spells the same cut as JSON fields. The [tool-call formatter][mini-format] puts the rendered text in `content` and the raw command output in `extra.raw_output`. That is not a model-callable archive handle. The default template suggests redirecting a command to a file; it does not thereby save this execution's output to one.
- **Pi v1.5.2** (`b4afdddf`). [Text file reads][pi-read] return the **head of the requested range**, limited by [2,000 lines or 50 KiB][pi-caps], with a continuation offset. A single oversized first line gets guidance rather than partial file contents. Continuing at that path reads the *then-current file*. In contrast, the shell tool's [text result][pi-bash] shows the **tail** and, on truncation, names a temp file for this execution. Its [accumulator][pi-acc] writes the raw chunks, including the buffered prefix. Its separate [programmatic output][pi-structured] can keep both ends under a larger cap. Neither the head-only read nor the tail-only shell text is the proposed two-ended historical preview; a temp path is useful only while the captured file exists.

## After results have entered the conversation

- **SWE-agent** (`3ea751c0`). Each [agent step][swe-step] uses [`messages`][swe-view], a history view filtered by agent and passed through configured processors. The optional [`LastNObservations`][swe-last] operates there. It indexes non-demo observations, spares the first (the task template), and normally keeps the last `n`. With `polling=p`, the exclusion boundary advances in multiples of `p` rather than on every query. Tags can override selection; `remove_output` wins over `keep_output`. The processor copies each elided entry and replaces just its content with omitted line/image counts. No digest or recall address is added. Its [trajectory test][swe-test] checks the number elided, not whether the task can still be solved. Batching limits the *frequency* of prefix edits; it does not guarantee cache hits.
- **OpenCode changed across revisions.** In **v1.1.47** (`6cd2a688`), the [prompt loop calls `prune` on exit][oc-loop], separately from the overflow check. [`prune`][oc-prune] walks backward, starts counting only after encountering two user messages, skips `skill`, and considers completed tool parts. Once cumulative candidate output exceeds 40,000 estimated tokens, the **crossing part itself** and older eligible parts are candidates. A previous summary or compacted part can stop the scan. Only if their total is **over** 20,000 does it stamp `time.compacted`. [`toModelMessages`][oc-msg] then sends a cleared-output marker and no attachments, but keeps the tool-call ID and input. The stored part was marked, not replaced with a digest-addressed recall tool.
- At **`656c2736`**, OpenCode's [automatic compaction][oc-auto] can hold a background summary until a swap is due rather than immediately rewriting a warm prefix; precomputation checks model identity and cache age. The [fallback transcript for the summary][oc-fallback] shortens exchanges oldest first, one level across exchanges before the next. It [clips tool results][oc-clip] to half the [2,000-code-point allowance][oc-levels] per end, then omits them, eventually leaving only user text or omitting an exchange. That is **input to compaction**, not a general read tool. The separate [`ToolOutput.truncate`][oc-tool] keeps a *head*, attempts to save joined result text, and explicitly says when saving failed. Its [seven-day retention policy][oc-retain] is not permanent, lossless storage of a result envelope.

## Below the harness

**ObsDrop** (`2a40d372`) leaves prompt token IDs in place. Its vLLM [policy][obs-policy] identifies complete blocks inside older delimited observations, protecting the newest `K`, delimiters and partial edge blocks. The [scheduler][obs-sched] walks only the reachable cached prefix and returns null blocks for dropped hashes; the [worker][obs-worker] removes those slots from attention. A new cache miss can require recomputation. This requires engine changes, not a message rewrite a client can request. The authors [report][obs-results] 46.7% solved without compaction versus 46.8% at `K=8` on 200 SWE-bench Verified tasks, Qwen3-Coder-30B-A3B, three repetitions; steps rose from 53.9 to 57.1. These are reported results, not our replication or evidence for a client-side selector.

## What to test here

1. **Late eligible first:** keep the [pressure gate and eligibility checks][local-plan] at baseline `141cfd7c`. Select the latest *already cold* eligible targets first until the same release/batch rules stop selection. Moving the first changed token later may preserve a longer reusable prefix; it may also hide more useful evidence. If every eligible target must be edited, reordering alone cannot move the boundary. A cache of printed tool results or a collapsed UI is not a provider prefix cache. Inspect the actual requests and reported usage, not display length.
2. **Preview vs pointer:** on the same selected result, keep at most **160 UTF-16 code units per end** (≤320 verbatim units; marker extra), with an explicit gap and the existing [branch/entry/digest-verified read][local-read]. Do not split a surrogate pair. A preview may show a heading and exit status while hiding the decisive line. Read the historical result, not today's file or a rerun of yesterday's command. Measure edge **and middle** lookups, no-revisit controls, first changed prefix, recall calls and replay, fresh/cached tokens, elapsed time and exact answers. Compare selection order separately from preview size. These are analogues, **not** implementations of upstream algorithms or grounds to change defaults.
