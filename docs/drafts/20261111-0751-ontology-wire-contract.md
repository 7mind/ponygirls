# Ontology wire-contract generation

The application supports its sole, unpublished `ontology.api` 0.1.0 contract. This work does not add service deployment or authorize model traffic.

## Owners and artifacts

- `ontology/models/ontology.baboon` remains the model source. The generator verifies the pinned Baboon 0.0.198 executable digest.
- `ontology/generated/schema-input/` preserves raw compiler OpenAPI components. These are **not** the accepted wire schemas: their ADT and nullable-field conventions differ from the application's codec/boundary contract. Do not serve these files as MCP schemas.
- `ontology/scripts/schema-registry.ts` reads executable generated codec metadata. It checks the type/component bijection and ADT parent/member correspondence, without parsing generated source or Baboon syntax.
- `schema-plan.ts` compiles the known component subset into a finite validation plan. Unsupported formats, keywords, unions, unresolved references and non-consuming reference cycles reject generation.
- `ontology/generated/wire/` contains the checked plan, schema bundle, reachable MCP schemas and codec fixtures. `ontology/generated/typescript/GeneratedWirePlan.ts` is generated by the same application-owned pipeline; do not edit it manually.
- Scala `WireSchemas` validates before generated decoding, including through `StoredJson`. Stored records retain their separate size boundary and canonicality check.
- Browser `WireValidation` checks and normalizes only schema-identified i64 values before decoding. `ApiClient` receives it explicitly. No runtime schema compiler or unsafe-eval is introduced.
- `CompiledToolSchemas` supplies the actual MCP transport schemas. These are representational contracts, not authorization, semantic truth, applicability or execution permission.

## Primitive and shape policy

Objects are recursively closed. Every field is required, including nullable fields; null is not interchangeable with omission. ADTs are exact one-key wrappers. Arrays and primitive kinds are checked without general coercion or default insertion.

i32 is integral numeric JSON within signed-32 bounds. i64 accepts exact integral numeric JSON or strings using JSON integer-token grammar (optional minus; zero or nonzero-leading decimal digits). `-0` is accepted. Plus signs, leading zeroes, whitespace, hexadecimal and exponent strings are rejected. Signed-64 bounds are checked before narrowing. Encoders retain decimal-string i64 output. UUIDs use full 8-4-4-4-12 hexadecimal spelling without an invented version restriction.

Browser parsing preserves numbers, bigint and strings. Only i64 positions can normalize to decimal strings. A large numeric actor identifier does not become a valid string field. Existing UTF-8, duplicate-key, byte and nesting protections remain. Decimal/exponent tokens are compared with the exact decimal meaning of their proposed JavaScript conversion before that value is accepted. Rounding a fraction into an integer and underflow into zero reject; tested exact forms such as `1.0` and `100e-2` remain supported. Existing rejection of unsafe noncanonical integer spellings such as a large integer followed by `.0` remains.

Portable schemas serialize exact mathematical numeric bounds. Ordinary JavaScript numeric schema comparison cannot establish signed-64 endpoint precision; exact predecode checks and type-guided normalization remain authoritative. AJV 8.20.0 is development-only verification, not a browser runtime dependency.

## Regeneration and verification

From the repository root, provision the locked frontend dependency tree once:

```bash
nix develop .#backend --command bash -c 'cd ontology/web && npm ci'
nix develop .#backend --command bash ontology/scripts/generate.sh
```

Generation compiles the metadata exporter and checks actual TypeScript codec roundtrips before writing the validation artifacts. Tests compare regenerated plans/schemas and model/raw-component digests, exercise every registered type and ADT member, and include required-field, wrong-type, integer-boundary and metadata-miswiring negatives.

```bash
nix develop .#backend --command bash ontology/scripts/test-postgres.sh
nix develop .#backend --command bash -c 'cd ontology/web && npm run typecheck && npm test && npm run build && npm run test:browser'
```

Scala fixtures validate actual generated TypeScript wire values through Scala codecs; branch fixtures use their parent wrapper for the generated Scala registry. This verifies representation correspondence, not domain admission. The full backend and browser runs remain necessary, and scripted browser success is not real-backend or Human-study acceptance.
