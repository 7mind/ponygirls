## Design and invariants

- Reuse `cuckoo.report` session entries and their existing version-aware validation. No separate memory store, cross-session search, new inference, or scheduler changes.
- Expose `cuckoo_recall` list/read, defaulting to the current branch; explicit session scope labels other branches. Entry IDs identify rounds. Enumeration is newest-first, cursor-based and bounded; text reads are paged.
- Preserve invalid/interrupted answers and legacy missing fields; never promote model-recalled rules or progress to verified evidence or permission. Expose reflection text, not private thinking blocks.
- Model guidance explains context-growth cadence, JSON-only checkpoints and resumption, recall availability while scheduling is off, historical scope and current-evidence checks.
- Put recall projection in a dedicated pure module over session entries and registration/guidance at the extension boundary. Rejected: a UI-text adapter (loses typed provenance and pagination) and a new persistent store (duplicates branch/lifecycle ownership already provided by Pi).
