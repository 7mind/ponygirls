# Input-only private comparison port

The initial generic engineering code was written before Root read any new episode narrative, private case, reference solver or solution; later implementation epochs and their read boundaries are disclosed below. It is NOT a standalone sandbox or execution release. Runtime owns `private_execution.py` confinement and receipt glue; it must not import candidate code in its credentialed controller.

`private_cases.py`:

- `parse_case(raw)` accepts exactly flat `{id,function,args,expected}`. Expectations are `kind:value/value:JSON` or `kind:exception/type:<builtin Exception name>`. Parsed argument/expected values are immutable canonical JSON bytes. Admitted built-in exception aliases are normalized to the class's canonical name (IOError/EnvironmentError become OSError); comparison is of that canonical class-name label, not a claim to authenticate process exception objects or apply subclass matching.
- `call_bytes(case)` emits ONLY `{function,args}`. Private case IDs, expected values, reference code, future input and evaluator results never enter this input channel.
- `assess(case, ProcessOutcome)` returns `CaseAssessment`: adequateTrue/False/None, category, canonical actual response orNone, raw stream digests, execution status/exit. Incomplete capture/input delivery, unavailable execution and child protocol failure remain unavailable; nonzero candidate exit, malformed output or returned mismatch are observed inadequate. Pipe bytes sent are not proof of consumption.
- `evaluate_cases(cases, invoker)` calls `invoker.invoke(payload:bytes)->ProcessOutcome`, preserving each case. Its adequacy is functional return/exception behavior ONLY.
- `apply_policy(report, require_unchanged_arguments:bool)` explicitly combines functional adequacy with required argument-state evidence. The caller derives this requiredBool from the applicable public intent, never from a missing observation. This is not a full-intent evaluator. A knownFalse remainsFalse even if another case is unavailable; complete coverage is separate. Empty inputs yield unavailable, not vacuous success. These functional results do not establish whole-scenario or Human acceptance.

`candidate_child.py` runs ONLY in an already-confined child: argv is the trusted primary module path (`/work/solution.py` for measured use), stdin is the call bytes. It loads that module through importlib, redirects ordinary module/function prints to stderr, and emits one JSON value/function-exception/candidate-error/protocol-error envelope on stdout. It never imports the private comparison module or accepts expected data. Valid dataclass modules are registered normally; cyclic/non-JSON returns are rejected rather than consumed indefinitely. Output is untrusted process behavior, not authenticated execution against malicious in-process interference. Expected values remain outside it.

## Net argument-state observation

The child additionally reports `argument_observation` with canonical argument JSON `before_bytes/before_sha256`, `after_bytes/after_sha256`, `after_status` and an exact Boolean `mutated`. The before identity must match the actual private call's canonical arguments. A normal JSON after-state must have a consistent changed/unchanged digest+length; a non-JSON after-state is explicitly marked and never called unchanged. Parent assessment keeps `arguments_mutated` (True/False/None) and `argument_evidence` independently from functional adequacy. Missing/null/invalid evidence is unknown, not unchanged. Raw private stdout retains the complete observation; `actual_utf8` describes the functional response separately.

This is observed NET canonical argument state before import/call versus after call/exception. It does not prove no intermediate mutation/restoration, immutable Python objects, honest hostile in-process reporting or exception-object authentication. An implementation that mutates then restores is net unchanged under this observation. Expected/reference data still never enter the child. Known functional or argument-policy failure is preserved even when other evidence is unavailable. `CasePolicyReport.complete` means every combined case decision is determinate, NOT that every required component was observed. `required_evidence_complete` separately requires known functional evidence and, when requested, known argument-state evidence for every case. Thus one known functional failure with missing argument evidence yields adequateFalse/completeTrue/required_evidence_completeFalse; neither an unknown case nor missing evidence is erased.
