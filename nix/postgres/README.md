# Explicit shared PostgreSQL 18 provider

Exports: `homeManagerModules.service-postgres` and
`nixosModules.service-postgres`. Both configure `ponygirls.servicePostgres`;
applications **consume explicit connections**, never enable their own cluster.
The provider/database set must remain enabled independently of application flags.
No automatic database deletion, credential rotation, old-cluster adoption or
cross-major data-directory reuse exists.

```nix
ponygirls.servicePostgres = {
  enable = true;
  stateDirectory = "/NEW/explicit/ponygirls-postgres-18";
  port = 15434; # operator can explicitly retain 15433 while moving state
  maxConnections = 64;
  adminReserve = 8;
  databases = {
    haystack = { passwordFile = "/run/secrets/haystack-database"; maxConnections = 8; };
    manure = { passwordFile = "/run/secrets/manure-database"; maxConnections = 8;
      schemas = [ "public" "manure" ]; };
    chronicle = { passwordFile = "/run/secrets/chronicle-database"; maxConnections = 12;
      statementTimeoutMs = 30000; lockTimeoutMs = 35000; idleTransactionTimeoutMs = 60000; };
  };
};
```

`databases.KEY` also accepts explicit `name`, `user`, `schemas` (default public),
`createPassword=false`, `statementTimeoutMs=30000`, `lockTimeoutMs=5000`,
`idleTransactionTimeoutMs=30000`, `workMem="4MB"`. Chronicle-keyed roles default
to lock=35000ms and idle-transaction=60000ms, matching its preserved long-lock
contracts. Chronicle consumers default to statement/lock/idle/socket=30/35/60/35s;
stricter explicit role or runtime limits still win. Generated missing credentials
require **explicit** `createPassword=true`; existing files and role verifiers are
preserved. Replaced/wrong credentials fail authentication, never silently rotate.
Managed credential symlinks (agenix) resolve under trusted operator directories;
regular-target precheck, NONBLOCK/NOFOLLOW open, fstat, private permissions and
bounded strict UTF8 reads reject special files, including writerless FIFOs.
PostgreSQL-compatible Unicode3.2 SASLprep/raw fallback preserves Unicode secrets.

Database/schema owners remain administrative. Runtime roles are not superusers,
have no DB CREATE, role creation, replication, bypass-RLS or memberships. Exact
loopback IPv4 database/role SCRAM HBA entries follow the local peer admin rule;
all other local/TCP access is rejected. PUBLIC CONNECT and schema privileges are
revoked. Provider installs vector and pg_trgm per database before readiness.
Manure's schema must be explicitly provisioned: PostgreSQL checks database CREATE
even for `CREATE SCHEMA IF NOT EXISTS` when the schema already exists, so service
bootstrap must guard the CREATE itself. Broad DB CREATE is not a workaround.

## Lifecycle and connections

- HM: `ponygirls-postgres.service`, independent `ponygirls-database-KEY.service`.
- NixOS: the **existing sole** `postgresql.service`, same per-database units.
- Readonly `connections.KEY` exposes `jdbcUrl`, `databaseUser`,
  `databasePasswordFile`, `maxConnections`, `readinessUnit`.
- Readonly `manifestFile` exposes the nonsecret backup-tool manifest.
- Each service has its **own** migration unit, ordered after its own setup and
  database readiness, not after a model server. Serving depends on that migration.
- Provider units contain no application package references. App/UI/package
  changes cannot restart the provider or unrelated applications. A database
  service does not claim systemd restart propagation; JDBC reconnect behavior is
  exercised separately, and provider restart is an intentional shared failure.

HM processes share one Unix UID and can read each other's credentials; SQL role
ACLs do **not** provide OS isolation. Use NixOS separate system users/LoadCredential
for that boundary. Existing API credentials/cookie codecs/state directories are
not renamed or regenerated by database migration. Manure payload `dataDirectory`
(HM) / `dataDir` (NixOS), optional `migrationReceiptDirectory`, and operator
credential/state directories are independently configured.

## Resource/privacy policy

Typed cluster fields: `sharedBuffers=128MB`, `effectiveCacheSize=4GB` (planner
estimate, not allocation), `maintenanceWorkMem=64MB`, `trackIoTiming=false`,
`randomPageCost=4.0`, `effectiveIoConcurrency=1`, `maintenanceIoConcurrency=10`.
These are conservative defaults, **not** measured deployment tuning. Existing
host-specific settings must be transferred explicitly. Sum role limits plus admin
reserve must fit maxConnections. Fsync, full-page writes and synchronous commit
remain on; no SSD assumptions or durability shortcuts. Per-service JDBC has all
8 finite limits; separate embedding admission bounds must leave serving capacity.

Role-scoped SQL privacy suppresses statement/duration/parameter logs and native
ERROR messages (which themselves may contain cast/constraint values). Admin and
cluster diagnostics are unchanged. Service telemetry must remain sanitized;
server-side raw SQL error diagnostics are intentionally unavailable for app roles.
Tests exercise actual inline, bound-parameter and constraint canaries in PG logs.

## Explicit backups/rehearsals, not activation

`packages.service-postgres-tools` ships:

- `ponygirls-postgres-backup cluster --manifest MANIFEST --output NEW_DIRECTORY`:
  all complete logical databases, private global role/password-verifier/config
  defaults, file digests. No WAL/PITR or cross-database atomicity claim.
- `ponygirls-postgres-backup manure-matched --manifest MANIFEST --output NEW_DIR
  --payload-root ROOT --migration-receipt-root CONTROL --config CONFIG --quiesced`:
  full Manure database + payload/staging/live/sidecars and optional migration
  control, under both exact physical-root claims. Source/copy inventories and
  config identity must match; completion is marked only last. This is **not** an
  online snapshot algorithm: stop admission, sweeper/recovery/workers and external
  writers first. Credential/config backups remain private operator responsibilities.
- `manure-offline`: separately packaged service-owned SQLite conversion/snapshot
  tool, never imported by the production Scala server or portable clients.

Outputs are new 0700 directories/0600 files. Failures retain incomplete private
outputs for inspection, never overwrite/adopt them or print SQL/credentials.
No restore, rollout, credential rotation or old-state deletion is performed.
Rehearse logical migration to a separately named shared cluster; keep old clusters
untouched/read-only until an explicitly approved rollback boundary. Q10 activation
is not implied by package/module validation.

Checks: `shared-postgres` (real disposable PG18, strict named inventory and source
binding), `shared-postgres-modules` (actual HM/NixOS provider adapters), existing
service/module checks, and native behavioral gates. PostgreSQL rehearsal includes
negative role/DB/admin access, effective and executed timeouts, privacy, mixed
workloads, restart/reconnect, individual DB restore, fresh-host global roles plus
all databases restore, credential preservation/FIFO/Unicode, shipped backup and
matched snapshot tools. These do not replace full JVM/browser/native domain and
migration/recovery suites; a built ELF or Nix evaluation alone is not acceptance.

### NixOS first-boot mount boundary

The stock NixOS PostgreSQL unit mounts a custom `dataDir` via `ReadWritePaths`
**before** any `ExecStartPre`. The shared provider's data directory must instead
remain absent until the no-adoption initializer creates it and its ownership
marker. Precreating even an empty unmarked data directory is deliberately refused.
The adapter therefore transforms only stock's `${stateDirectory}/data` aperture
into the exact existing, private `stateDirectory` aperture, allowing legitimate
marker/socket/data writes there. Other separately configured operator apertures
are preserved; unsupported non-list forms fail explicitly. `ProtectSystem=strict`,
all other stock hardening, `User=postgres`, and provider ownership/major/identity
checks remain unchanged. This is not a broad `/var/lib` write allowance and does
not authorize activation or adoption of any existing cluster.

### Strict files versus systemd's UID-ACL credentials

Ordinary files (including HM) retain the original `077` group/other permission
rejection, managed-reference/regular-file/bounded UTF-8 rules and password
preservation. `0400`/`0600` private files remain supported. No generic group-read
exception or new fallback is introduced.

Only the NixOS database provisioning command selects the explicit
`--loaded-systemd-credential` policy for an existing `LoadCredential` reference.
It is bound to the expected `postgres` Unix identity and exactly
`/run/credentials/ponygirls-database-KEY.service/database-password`, not an
arbitrary environment-provided directory. Directory descriptors are walked with
`O_NOFOLLOW`; root-owned ancestors must be non-writable and have no extra ACLs.
The root-owned `0550` unit directory and `0440` regular file must have exactly
systemd's observed named-service-UID access ACL: owner read/execute (directory)
or read (file), one named UID with the same permissions, **empty group object**,
matching mask, empty other. The apparent group bits are the ACL mask, not group
access. No extra entries/default ACL, symlink, writable/world-readable metadata,
foreign identity or descriptor/path identity mismatch is accepted. The final
file is opened relative to the bound directory and the same 4096-byte/single-line
UTF-8 decoder is used. No secret staging, chmod, role or authentication change.

The pinned systemd `write_credential`/`credentials_dir_finalize_permissions`
source and actual owned-VM metadata establish this transport shape. Fast contract
cases compare ordinary real files and a hand-written descriptor adapter; the
real `LoadCredential` FD/UID leg and controlled negative metadata/reference
cases run before actual provisioning in the lifecycle VM. No metadata-only
probe substitutes for the mandatory real-systemd positive/matrix run.
